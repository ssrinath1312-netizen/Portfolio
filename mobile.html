The problem

Educational institutions relied on two separate legacy ERP systems, one for schools and one for colleges, each deployed as independent instances with no shared data or unified workflows. This caused data duplication, operational inefficiencies, high maintenance costs, and zero visibility across institution types. NetKampuss was built to unify both into a single multi-tenant SaaS platform serving Schools (CBSE/ICSE/IGCSE/State Board), Colleges, Group of Institutions, and Private Universities.

My approach, click each phase to explore
Key challenge resolved

Student 360 View Dashboard, conflicting stakeholder priorities

The Student 360° View Dashboard required aggregating data from seven source modules, Student Information, Attendance, Fee, Academics, Health, Counselling, and Extra-curricular, into a single unified screen. Stakeholders from administration, teaching, and parent groups had conflicting priorities on what data to surface and at what granularity. Through structured prioritization workshops and data dependency mapping across all source modules, I designed role-based views so that each persona, Admin, Teacher, and Parent, sees only the data relevant to their context, within a single dashboard.

US-FEE-012 · NetKampuss · Fee Module
Fee payment with auto-receipt generation
+
"As a parent, I want to pay my child's school fee online and receive an instant receipt, so that I have proof of payment without visiting the school."
Acceptance criteria
  • System displays outstanding fee breakup (tuition, transport, activity) before payment
  • Payment supports UPI, debit/credit card, and net banking via integrated gateway
  • PDF receipt generated within 5 seconds and sent via email and SMS on success
  • Receipt includes student name, fee head, amount, date, and unique transaction ID
  • Failed payment shows clear error message and does not deduct fee balance
  • Manual override: admin can mark fee as paid offline with a mandatory reason field
US-SM-004 · NetKampuss · Student Management
Bulk student data update
+
"As an Institutional Administrator, I want to download, edit, and re-upload bulk student data so that large-scale data corrections can be completed quickly without updating each record individually."
Acceptance criteria
  • Admin can filter and select target students by Academic Year, Class, Section, or Admission Batch before initiating a bulk update
  • System generates a pre-filled downloadable template containing both system and custom fields for the selected student group
  • On re-upload, system validates the file format and field mapping before applying changes
  • Invalid or conflicting records are flagged with clear error messages and excluded from the update batch
  • All changes are logged in the audit trail with user ID, timestamp, and fields modified
  • Admin receives a post-upload summary report showing success count, failure count, and skipped records
US-LP-001 · TL-PAY · VKYC Module
Video KYC verification, Gherkin format
+
"As a customer, I want to complete my KYC verification through a live video call so that my identity is verified securely without visiting a branch."
Acceptance criteria, Gherkin scenarios
  • Scenario: Customer completes VKYC successfully
    Given the customer has completed the loan application form
    And the application status shows "Proceed to Video Verification"
    When the customer selects their preferred language
    And proceeds to the Hyperverge portal and grants camera, microphone, and location permissions
    Then the system connects the customer to a KYC associate
    And the associate captures the customer's ID card via back camera
    And captures a live selfie via front camera for face match
    And the system auto-verifies the captured data
    And KYC status is updated to "Approved" upon successful verification
  • Scenario: Customer fails internet speed check
    Given the customer has granted all permissions
    When the internet speed check fails
    Then the system displays a clear error message
    And offers the customer an option to retry or schedule the call for a later time
  • Scenario: Duplicate or impersonation detected
    Given the KYC associate has captured the customer's live selfie
    When the face match against the ID card photo fails
    Then the system flags the application for manual review
    And the KYC status is updated to "Verification Failed"
    And the customer is notified with next steps
